# Data grounding

**The rule this repository is built on: nothing is invented.**

Every label is either downloaded from an open database, or computed from downloaded
data through an equation that is written down and cited. Where a number is a proxy
for something else, it is named as a proxy everywhere it appears — in the column
name, in the figures, and in the text.

This file says which is which. It is the first thing to read if you want to know
how much to trust anything here.

![Data provenance](results/figures/fig3_data_provenance.png)

## The four tiers

| Tier | Meaning | How much to trust it |
|---|---|---|
| **1e** | **Measured** in a laboratory | The closest thing to ground truth available. Also the rarest. |
| **1** | **Calculated** by DFT, by someone else, published and cited | Real data, but carrying DFT's own systematic errors — see below |
| **2** | **Derived here** from Tier 1 data via a published equation | Only as good as its inputs and the equation's assumptions, both stated |
| **3** | **Synthetic** — generated by us | Never a result. Used only to check that the code can recover a relationship we planted |

## Target by target

### Band gap — Tier 1 (DFT) and Tier 1e (measured)

- **Tier 1:** Materials Project and JARVIS-DFT `band_gap`.
- **Tier 1e:** `matminer` `expt_gap`, ~4,600 measured values.

**The known problem, stated up front.** Standard DFT (GGA) systematically
underestimates band gaps, often badly. This is not a database defect, it is a known
limitation of the exchange-correlation functional. A model trained on Tier 1 labels
learns to reproduce DFT — *including its errors* — not to reproduce reality.

The sibling repository [`MPExplorer`](https://github.com/teja2792/MPExplorer)
documents three distinct verified failure modes across the four materials in our
snapshot, including a ~75% underestimate of the Cu₂O gap. Having both tiers here
means the size of that inherited error can be **measured** rather than asserted.

**Never mix functionals.** GGA, GGA+U and r2SCAN gaps are different quantities.
Every analysis in this repo groups by `dft_run_type` before computing anything.
The one place this bites hardest is Fe₂O₃, whose entries are all GGA+U.

### Formation energy per atom — Tier 1

Materials Project and JARVIS-DFT. Better behaved than band gaps: formation energies
from GGA are generally accurate to a few tens of meV/atom for oxides. Still a
calculated number, not a calorimetric measurement.

### Stability — Tier 1

Materials Project `energy_above_hull`: how far a material sits above the convex hull
of competing phases, in eV/atom. Zero means it is on the hull.

**"Stable" is a modelling statement, not a physical one.** It means *stable within
this database's set of computed competing phases, at 0 K, at zero pressure, ignoring
entropy*. Our snapshot illustrates the consequence nicely: of 44 TiO₂ polymorphs,
DFT puts **anatase** on the hull, not rutile — while rutile is the thermodynamically
stable phase under ambient conditions in reality. That disagreement is real, known,
and worth keeping in view whenever a model is asked to predict "stability".

### Adsorption energy — Tier 1

Catalysis-Hub (primary) and OC20 IS2RE-10k (stretch). Real DFT numbers from published
studies.

**A modelling caveat that is not a data caveat:** these are surface slabs with
adsorbates, not bulk crystals. A model trained on bulk crystal graphs is being asked
to work on a genuinely different kind of object. Phase 7 measures that domain shift
explicitly (zero-shot transfer vs. fine-tuned vs. trained from scratch) rather than
assuming it is small.

### Catalytic activity descriptor — Tier 2, derived

**This is not a measured rate, and this repository never claims it is.**

No dataset exists that pairs crystal structures with measured catalytic activity at
the scale a neural network needs. Rather than invent one, we compute a *theoretical
activity descriptor* from real adsorption energies using the standard scaling-relation
framework:

| Reaction | Descriptor | Activity proxy |
|---|---|---|
| Hydrogen evolution (HER) | ΔG<sub>H*</sub> | volcano relation on \|ΔG<sub>H*</sub>\| |
| Oxygen evolution (OER) | ΔG<sub>O*</sub> − ΔG<sub>OH*</sub> | theoretical overpotential, standard four-step mechanism |
| CO oxidation / CO₂ reduction | ΔG<sub>CO*</sub>, ΔG<sub>O*</sub> | binding-energy descriptors |

Every input is a real DFT number. The transformation is a citable equation. The exact
equations and citations go here as Phase 7 is built.

**Naming discipline.** The column is `activity_descriptor_theoretical`. It is never
called `activity`, `rate`, or `TOF`. Figures using it say "descriptor" in the axis
label. This is deliberate: a proxy that gets casually renamed becomes a false claim
two slides later.

**And a caveat that matters more than it sounds.** Activity depends *exponentially*
on binding energy. A ±0.2 eV error in a predicted adsorption energy — perfectly
respectable for a model — becomes a large multiplicative error in the derived rate.
Phase 7 quantifies this propagation. Screening rankings from these numbers are only
meaningful down to a resolution that error analysis supports.

### Synthetic oracle — Tier 3

`src/synthetic_oracle.py` (Phase 3). A toy target with a known functional form,
used for one purpose: confirming the model can recover a relationship that was
deliberately planted. If it cannot recover a known signal, any result on real data
is suspect.

This is the same role the oracle plays in
[`CatalystBO`](https://github.com/teja2792/CatalystBO). It is a test fixture. It is
never a prediction target, never a headline number, and never appears in a results
table alongside real data.

## What this repository does not predict

- **Measured catalytic rates** — turnover frequency, current density, faradaic
  efficiency, product selectivity. No structure→measured-rate dataset exists at the
  required scale. See the activity descriptor section above for what we do instead.
- **Anything under realistic reaction conditions.** All source calculations are 0 K,
  vacuum or implicit solvent, static geometries. Real catalysts operate hot, wet,
  under potential, and they restructure while they work.
- **Synthesisability.** A structure being on the DFT convex hull does not mean anyone
  can make it.

---

## Where this leaves you

The honest summary: this repository predicts **what DFT would have said**, having
learned from what DFT did say. That is genuinely useful — DFT is expensive and a
trained model is not — and it is a smaller claim than "predicts material properties".
Both statements are worth keeping straight.
